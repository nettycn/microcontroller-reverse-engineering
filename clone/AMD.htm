About AMD Microcontrollers

Advanced Micro Devices (AMD) is predominantly known for its x86 processors and GPUs, but it also has a rich history in microcontroller and embedded solutions. In the 1980s and 1990s, AMD produced a range of microcontrollers, including the Am186 and Am386 series, which were x86-compatible embedded processors. These devices were used in industrial controls, telecommunications, and early PC peripherals. AMD also developed the Am29xx family of bit-slice processors and the Am25xx series of logic devices. More recently, AMD's embedded product line includes the G-series and R-series accelerated processing units (APUs) that integrate CPU and GPU cores for low-power applications. In addition, AMD has offered flash memory products, such as the Am29F series, which are widely used as boot flash for motherboards and embedded systems. These flash devices store the firmware (BIOS/UEFI) and are critical targets for reverse engineering. Although AMD does not currently produce standalone microcontrollers like ARM-based MCUs, their x86 embedded processors and flash memory chips are essential components in many systems. Our reverse engineering services cover AMD's embedded x86 processors, flash memory, and associated firmware. We have extensive experience extracting firmware from AMD flash chips, even when readback protection is enabled. For the Am186 and Am386, we can replicate the functionality and extract the internal ROM code through decapsulation and microprobing. AMD's processors often include security features such as Secure Boot, Trusted Platform Module (TPM), and encrypted memory. However, these can be bypassed using advanced side-channel attacks and fault injection. Our team has successfully recovered encryption keys from AMD's PSP (Platform Security Processor) and has extracted BIOS images from locked flash devices. We also provide cloning services to duplicate AMD flash contents for legacy system replacement. AMD's embedded APUs are used in medical imaging, industrial PCs, and automotive infotainment, making their firmware highly valuable. We have developed specialized tools to read the SPI flash connected to AMD processors, even when the readback is disabled. By using voltage glitching and clock manipulation, we can trick the flash into allowing reads. For the older Am29F series, we can use standard programmers, but if the device is locked, we apply UV erasure or decapsulation to access the memory cells directly. Our lab is equipped with high-precision soldering stations, logic analyzers, and custom flash programmers. We have also reverse-engineered the communication protocols between the AMD CPU and its peripheral devices to extract configuration data. AMD's security features have evolved with each generation, but our team stays up-to-date with the latest techniques. We have published several papers on attacking AMD's secure boot process, using side-channel analysis to recover the bootloader. Our methods are non-destructive where possible, but we also offer invasive decapsulation for deep analysis. Whether you need to recover a lost BIOS, clone a flash chip, or understand the security of an AMD embedded system, MikaTech provides comprehensive solutions. Our success with AMD products includes extracting encrypted UEFI payloads and reverse-engineering the initialization code for custom hardware.

Security Features and Reverse Engineering Techniques

AMD’s embedded processors and flash devices incorporate multiple security mechanisms to protect firmware and configuration data. For flash memory, the most common protection is the use of block lock bits that prevent write and erase operations, as well as readback protection that restricts reading the memory contents. The flash device can also be set to a secure mode where the entire array is locked and can only be unlocked by a specific command sequence. Some AMD flash chips have a hardware write-protect pin that, when asserted, disables all programming functions. Additionally, many AMD APUs feature a secure boot process that validates each stage of the firmware using cryptographic signatures. The boot ROM checks the signature of the bootloader, and if verification fails, the system halts. This prevents loading of unauthorized firmware. The Platform Security Processor (PSP) inside AMD chips manages the secure boot and also provides a trusted execution environment. However, these protections are not infallible. Our reverse engineering team has developed multiple attack vectors. For instance, we can intercept the SPI communication between the CPU and the flash chip during boot, allowing us to capture the raw firmware as it is being loaded. This is effective even if readback is disabled, because the CPU still reads the data into memory. By using a logic analyzer, we can record the entire transaction and reconstruct the firmware image. We have also used glitching on the flash chip’s power supply to bypass the lock state, enabling us to perform a full dump of the memory. For devices with encrypted firmware, we apply side-channel power analysis to extract the encryption key from the CPU during the decryption process. By analyzing the power consumption while the CPU processes the encrypted data, we can recover the key and decrypt the firmware offline. For older Am186/Am386 devices, the internal ROM code is masked and cannot be read normally. We use decapsulation (removing the die) and then micro-probe the memory array to read out the bits directly. This is a time-consuming process but yields the complete ROM image. We have also employed fault injection to bypass security checks in the boot sequence, allowing us to execute custom code on the processor. Once we gain control, we can then read or modify the internal registers and memory. Our expertise extends to the Geode and other legacy x86 embedded devices, where we have successfully cloned the flash contents and recovered the BIOS. We also offer duplication of AMD flash chips for obsolete systems, ensuring you have a backup. Our lab is equipped with specialized tools for SPI sniffing, glitching, and microprobing. We have developed custom firmware for many common flash programmers to handle locked devices. Our team is experienced in recovering BIOS/UEFI images from motherboards and embedded systems, even when the manufacturer has intentionally locked the flash. We have also analyzed the security of AMD's PSP and have discovered vulnerabilities that allow extraction of confidential keys.
